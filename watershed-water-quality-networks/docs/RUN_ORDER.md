# Suggested run order and dependencies

Run from the repository root after setting `WRR_DATA_ROOT`. Each script writes results beneath that configured data directory unless its own output settings specify otherwise.

## Figure 2–4

1. `fig02_network_structure.R` — network structure panels; requires the TE-Net, Phys-Net, station, basin, and river inputs.
2. `fig03_directional_validation.R` — observational/directional validation; uses concentration, station, river/basin, and TE-result inputs.
3. Choose one Figure 4 script: `fig04_yield_castdm.R` for the revised yield comparison, or `fig04_load_comparison_legacy.R` for the earlier load comparison. Figure 4 scripts also expect precomputed PCS/Fusion-Net and other model/load inputs. The Figure 5 Step 2 script specifically reads `Fig4_final_independent/03_NTN_mean_annual_load.csv`, which is produced by `fig04_load_comparison_legacy.R`; run that script (or provide that exact input file) before Figure 5 Step 2. The newer yield-oriented Figure 4 script writes yield files under a different output folder and does not create that load file.

## Figure 5 anomaly-triggered monitoring workflow

1. `fig05_step1_anomaly_catalog.R` — event catalog and observation-coverage products.
2. `fig05_step2_source_conditioned_pcs.R` — source-conditioned rankings; depends on Step 1 outputs and precomputed PCS/Fusion-Net products.
3. `fig05_step3_dual_lag_ranking.R` — lag-aware target ranking; depends on Steps 1–2 and physical/TE network inputs.
4. `fig05_final_optimized.R` — optimized figure using earlier step outputs.
5. `fig05_final_three_regions.R` — six-case regional figure using precomputed regional case tables; those tables are not generated by the supplied Step 1–3 scripts.

## Figure 6 independent evaluation workflow

1. `fig06_step1_training_networks.R` — constructs training-period networks and scores.
2. `fig06_step2_test_events.R` — constructs independent test events and common evaluation data.
3. `fig06_step3_fair_comparison.R` — ranks targets and compares methods.
4. `fig06_step3b_paired_gain.R` — paired incremental-value and uncertainty analysis; depends on Step 3 outputs.
5. `fig06_final_budget_comparison.R` — budget comparison and final figure; depends on Steps 2, 3, 3b, and associated training/physical-network outputs.

## Before publication or sharing

- Verify the scripts use the final manuscript definitions, thresholds, dates, and units.
- Check input filenames and columns against your local data.
- Keep raw data and generated results outside the Git repository unless you have permission and a clear reason to publish them.
- The supplied scripts have not been run here because their source data and intermediate result folders were not attached.

## Network construction and supplementary analyses

Before the figure workflows, use `scripts/networks/01_build_te_network.R` and `02_build_physical_network.R` to build the two constituent networks, then `03_build_fusion_network.R`, followed by `04_compute_pcs.R`. Physical-network construction requires the NHDPlus flow-direction inputs referenced in its path section.

`scripts/quality/` contains station-coverage, TE-data QA and robustness analyses. `scripts/supplement/` contains Figures S1–S6. Their own input sections specify the required precomputed results; run them after those results have been produced.

Figures S1 and S3 refer to `Fusion_Net_2011_2023`, whereas the supplied fusion builder writes `Fusion_DualLag_2011_2023`. Confirm the expected file schemas and provenance before connecting these products; directory renaming alone does not establish compatibility. Figure S4 reads the load-oriented Figure 4 station metrics. No analysis parameters were changed during packaging. The station-coverage output path was moved under the configured data root (`figures/Fig1_NTN_coverage`).
